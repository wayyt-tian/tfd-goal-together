# 产品范围与验收

## 用户目标

v0.3 要回答四个问题：**我和哪些目标有关、我的团队怎么样、公司整体走到哪了、刚刚发生了什么**。同时让任何人想到能带来增长的事，都能马上建起来挂到相关目标下面，上级和公司总览实时看到。整体调性是轻松、协同、共创，不做打分和排名，避免传统绩效系统的压迫感；在 50–80 人、第一次使用的情况下也要一眼看懂。

## 页面结构

顶栏只有 4 个入口，右上角一个全局「＋新建」。手机上是底部 4 个标签加一个浮动的「＋」按钮。

| 入口 | 谁能看到 | 内容 |
| --- | --- | --- |
| 我的 `#/` | 所有人 | 问候和一句话摘要（“今天有 N 件事值得看一眼”）；最新动态滚动条；「你不在的时候」摘要；收到的点赞；新手三步引导（只出现一次）；**我负责的 / 我参与的 / 我的自主目标**三组卡片，每张卡片顶上写着它属于哪个公司目标；有团队的人多一块「我的团队」概览和锅气小助手 |
| 目标地图 `#/map` | 所有人 | 公司北极星目标卡片（完成度、时间进度、状态、末端目标分布）；点进去是目标页，逐层下探 |
| 目标页 `#/g/:id` | 能看到这个目标的人 | 顶部是路径（属于哪个上层目标）、完成度环、时间进度、负责人和协作者；三个标签：**拆解路径**（下一层目标和各自状态）/ **成员**（谁在推进、各自贡献了多少）/ **动态**（这个目标及下层的最新进展） |
| 团队 `#/team` | 有下属或管理部门的人、公司负责人 | 按部门折叠的成员列表，先显示需要关心的人（需要支持、落后、很久没更新、稍慢）；点人进入个人页 |
| 个人页 `#/p/:id` | 本人、上级、公司负责人 | 这个人负责和参与的全部目标、最近进展 |
| 动态 `#/pulse` | 所有人 | 全部 / 和我有关 / 我的团队（有团队的人才有）/ 需要支持 / 新目标几个筛选，按天分组，可点赞；侧栏是锅气小助手 |
| 我记过的进展 `#/me/records` | 本人（头像菜单） | 自己记过的每一笔，可以撤回 |
| 设置与成员 `#/admin` | 公司负责人（头像菜单） | 成员 / 组织 / 规则 / 已归档 / 数据 五个分栏 |

## 核心操作

| 操作 | 入口 | 要点 |
| --- | --- | --- |
| 新建目标 | 全局「＋新建」、目标页「加子目标」 | 一屏填完：标题、属于哪个目标、有数字（单位 + 目标值）还是做完就行、谁负责、周期。挂到自己参与或管理的任何目标下面 |
| 拆给成员 | 目标页「拆给成员」 | 一次选多人，每人一行（标题、份额、备注），提交后每人得到一个子目标；份额合计超过上层时只提示不拦截 |
| 记一笔 | 卡片上的「记一笔」、目标页 | 负责人和协作者填这次新增的数字（可不填，只留言），一句话说明可写可不写，三选一的感觉：顺利 / 有点担心 / 需要支持。其他能看到这个目标的人可以留言 |
| 自主目标 | 「我的」→ 发起自主目标 | 自己想推进的事，可以挂靠到公司目标表明方向；不计入公司汇总；本人、协作者和上级能看到 |
| 加入协作 | 目标页「加入协作」 | 看到想出力的公司目标可以自己加入，成为协作者后能记进展 |
| 完成 / 重新打开 / 归档 / 恢复 | 目标页菜单 | 归档整棵子树一起，可在「设置 › 已归档」恢复 |
| 撤回进展 | 目标页动态、我记过的进展 | 只能撤回自己写的，原因可写可不写；原记录保留、标记已撤回，汇总立即重算，也可以再恢复 |
| 点赞 | 任意动态 | 再点一次取消；对方在「我的」看到收到的点赞 |
| 一键交接 | 设置 › 成员 | 离职或演示角色名下的目标一次交给在职同事，历史记录人不变 |

## 验收场景

| 编号 | 场景 | 自动测试 |
| --- | --- | --- |
| AC01 | 员工登录后在「我的」看到自己负责、参与的目标，每个都能看到属于哪个公司目标 | test-goals |
| AC02 | 员工新建自主目标并挂靠公司目标；进度自己维护，不影响公司汇总 | test-goals |
| AC03 | 上级（汇报线或部门负责人）能看到下属的目标和进度；同级、其他部门看不到 | test-goals |
| AC04 | 公司负责人从公司目标逐层下探到末端成员，每一层的数字都能由下一层解释（同单位汇总、差额、隐藏子项计数） | test-goals |
| AC05 | 一人记进展后，相关的人在几秒内看到数字变化和新动态，不用刷新 | test-goals（增量）、手工实时检查 |
| AC06 | 任何参与者都能在目标下面加子目标；上级和公司总览看到“新目标” | test-goals |
| AC07 | 记进展只增不改：同一条重复提交只算一次，撤回保留原记录并可恢复；负数（冲减）要写原因，累计不能为负 | test-goals |
| AC08 | 同时编辑同一目标时后提交的人收到 409 并载入最新内容 | test-goals |
| AC09 | 权限全部由服务端判断：不可见的目标返回 404，无权操作返回 403 | test-goals |
| AC10 | 63 人演示 + 17 人补足到 80 人时，首页加载、数据量、动态和增量接口都在限值内；每个身份只看到自己范围 | test-scale |
| AC11 | 已有 PostgreSQL 升级前备份，旧记录保留，账号重新设置密码，独立库恢复通过；不迁移 SQLite | test-operations |
| AC12 | 通讯录导入：计划模式不写入，写入模式先备份，重复导入不重复建人 | test-import |
| AC13 | 页面引用的脚本、样式、图片都存在且可访问；不对外暴露源码目录和数据目录；IP 原图带字版本不在页面中使用 | test-static |
| AC14 | 手机和电脑宽度下 4 个演示身份的主要页面无脚本错误、无横向溢出 | 手工巡检（截图见 docs/screenshots/） |

## 明确不在本轮范围

奖金结算和绩效打分、审批流、自动提醒（短信、企业微信）、附件证据上传、跨周期的自动复制目标、公网部署和更强的身份验证、三级以上的部门。需要时由用户明确提出。

v0.4 补齐正式模式和管理闭环，新增账户、角色说明、导入、日志、备份及运行状态均位于现有登录页、头像菜单及设置分栏；详见 [正式模式与账号管理](14_正式模式与账号管理.md)。
