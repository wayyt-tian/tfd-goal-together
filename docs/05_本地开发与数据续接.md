# 本地开发与部署

当前数据库为 PostgreSQL 16；本轮不提供 SQLite 数据迁移，也不会打开旧数据库。历史升级说明已归档到 `docs/references/`。所有命令从项目根目录运行。

## 本地体验

需要 Node.js 22.13+、Docker、已缓存的 `postgres:16-alpine` 镜像。通讯录导入与相关测试需要 Python 3.9+，浏览器检查需要 Chromium。

```sh
npm ci
npm run db:setup
npm run demo
# 或 npm run demo:live
```

`db:setup` 仅在 `.env` 不存在时生成随机密码；不会覆盖已有配置。Compose 项目为 `goal-together`，容器为 `goal-together-postgres`，默认仅在本机 55436 端口提供数据库，持久卷为 `goal-together_postgres-data`。不停止、不复用其他项目的容器或数据卷。首次在新机器上运行需先准备对应镜像（例如 `docker pull postgres:16-alpine`）。

初始化脚本在数据卷首次创建时建立 `goal_together`、`goal_together_demo`、`goal_together_test` 三个库。已有卷不会重新执行初始化脚本。`npm run demo` 每次在演示库创建随机隔离空间，正常退出时删除；`--keep` 仅用于保留演示排查数据。异常强制终止可能留下临时空间，可由开发者核对名称后单独清理。

## 正式与演示共用入口

`npm run build && npm start` 默认提供 `/formal/` 和 `/demo/`，根地址进入正式模式；首次配置、账号、角色、导入、日志和恢复见 [正式模式与账号管理](14_正式模式与账号管理.md)。局域网使用 `HOST=0.0.0.0 PORT=4180 npm start`，其他设备访问本机局域网 IP。数据库仍仅监听本机。

## 配置与开发

| 配置 | 用途 |
| --- | --- |
| `DATABASE_URL` | 非演示服务的 PostgreSQL 地址 |
| `DEMO_DATABASE_URL` | 仅演示；库名必须以 `_demo` 结尾 |
| `TEST_DATABASE_URL` | 仅测试；库名必须以 `_test` 结尾 |
| `DATABASE_SCHEMA` | 服务隔离空间，默认 `public`；演示和测试自动生成 |
| `PG_POOL_MAX` | 连接池上限，默认 10，其中数据库监听使用一条连接 |
| `BACKUP_DIR` | 备份目录；未设置则为 `GUOQI_DATA_DIR/backups` 或 `.data/backups` |
| `HOST`、`PORT` | 默认 `127.0.0.1:4173` |
| `PUBLIC_ORIGIN` | 通过代理访问时填写实际站点地址 |

`.env` 不提交，也不打进镜像。远程环境可以直接注入环境变量，按 `.env.example` 设置三条独立连接；密码中特殊字符应进行 URL 编码。远程连接按需添加 `?sslmode=require` 并配置可信证书。测试账号仅授予专用测试库的隔离空间创建和删除权限，不授予正式库访问权。

开发时在两个终端分别运行 `npm run dev:server`、`npm run dev`，打开 `http://127.0.0.1:5173/`。Vite 将接口、品牌素材和字体代理至 4181 端口的临时演示服务。

```sh
npm run build
npm start
```

正式空库首次启动后，凭服务器本机初始化凭证设置公司负责人。不要用正式连接做开发验证。`GUOQI_DATA_DIR` 不再控制数据库连接，仅用于本地文件。

## 容器运行

```sh
docker compose --profile app up -d --build app
```

应用默认位于 `http://本机局域网地址:4182/`（`APP_BIND` 默认为 `0.0.0.0`）。镜像内含 PostgreSQL 16 客户端和 Python；运行进程使用非 root 用户。正式部署在反向代理与 HTTPS 后配置 `PUBLIC_ORIGIN`、备份保留与监控。Compose 中的数据库仅监听本机；远程数据库使用独立的环境配置启动应用镜像，不必启动本地数据库服务。

## 备份、恢复与导入

「设置 → 数据 → 下载备份」输出 `.dump`，为 PostgreSQL 16 自定义格式，不包含数据库密码。优先使用本机版本 16 的 `pg_dump`；开发机未安装时复用 `postgres:16-alpine` 运行工具。容器备份通过本容器内的客户端完成。

恢复应在新建的独立库验证，使用 PostgreSQL 16 的 `pg_restore --clean --if-exists --no-owner --no-acl --exit-on-error --single-transaction`，连接通过 `PGHOST`、`PGPORT`、`PGDATABASE`、`PGUSER`、`PGPASSWORD` 等环境变量设置。备份包含源隔离空间名称，恢复时保留其名称并设置 `DATABASE_SCHEMA`。确认人数、目标、流水和游标后再安排切换。不要直接覆盖正在使用的库。本轮测试已在随机测试空间实际执行备份和恢复。

通讯录导入保持原有业务规则，默认只给计划，`--apply` 才写入；写前备份并持有组织锁，写入事件后提交，通过数据库通知让在线页面刷新。只能对授权的数据使用；自动测试仅生成虚构 XLSX。

```sh
npm run import:contacts -- /绝对路径/虚构通讯录.xlsx
```

数据库结构初始化由 `schema_migrations` 记录，重复启动不会重复建表或重复播种演示数据。后续新增有数据的结构升级必须先备份、提供报告并单独验证恢复；旧 SQLite 数据的转换需另行明确方案。
