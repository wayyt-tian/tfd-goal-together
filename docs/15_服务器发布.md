发布入口为 [goal-together-release](../.agents/skills/goal-together-release/SKILL.md)，该目录随仓库交付。目标配置保存在 `deploy/production.json`，不含密钥：服务器 `ubuntu@120.53.31.57`，域名 `goal.tywldx.ltd`，目录 `/srv/goal-together`，应用端口仅绑定 `127.0.0.1:4182`。

## 换机器操作

克隆本仓库，准备 Python 3.10+、Git、OpenSSH，并取得自己的服务器 SSH 权限。先向管理员核对主机公钥指纹，再连接服务器建立可信主机记录。无需原开发机、本地 Docker、数据库、构建产物或 GitHub 登录态。

让助手读取仓库内的 skill；支持项目 skill 自动发现的助手也可使用 `$goal-together-release`。进入项目根目录执行：

```sh
python3 .agents/skills/goal-together-release/scripts/release.py plan
python3 .agents/skills/goal-together-release/scripts/release.py check
python3 .agents/skills/goal-together-release/scripts/release.py deploy --execute
```

正式发布要求代码已经审查、提交且工作区干净；`--ref` 可指定提交，`--identity` 可选择操作者私钥。工具只归档所选提交，不读取本地 `.env`。首次部署在服务器生成私有配置，正式与演示数据库隔离；测试在临时容器、网络和数据库中运行。备份、回退条件及目标机依赖见 [运维说明](../.agents/skills/goal-together-release/references/operations.md)。

## 镜像清理

每次发布通过隔离测试、备份及本机和 HTTPS 验证后，保留最近三个成功版本、当前版、上一版和所有容器引用的镜像。只逐个删除带本项目归属标签的旧应用镜像，不强制删除，不执行全局清理，不删除数据库、卷或备份。清理失败单独记入发布回执，应用发布状态不因此变成失败；可重试：

```sh
python3 .agents/skills/goal-together-release/scripts/release.py cleanup --execute
```

共享构建缓存和基础镜像不在清理范围，不能将此功能视为全服务器磁盘清理。
