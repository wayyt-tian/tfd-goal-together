## 换机器操作

克隆本仓库，准备 Python 3.10+、Git、OpenSSH、Docker，并取得自己的服务器 SSH 权限。本机需准备 `node:24-alpine`、`postgres:16-alpine` 基础镜像和依赖下载网络，Docker 架构与服务器 linux/amd64 一致。先向管理员核对主机公钥指纹，再连接服务器建立可信主机记录。无需原开发机、本地正式数据库或目标机 GitHub 登录态。

让助手读取仓库内的 skill；支持项目 skill 自动发现的助手也可使用 `$goal-together-release`。进入项目根目录执行：

```sh
python3 .agents/skills/goal-together-release/scripts/release.py plan
python3 .agents/skills/goal-together-release/scripts/release.py check
python3 .agents/skills/goal-together-release/scripts/release.py deploy --execute
```

正式发布要求代码已经审查、提交且工作区干净；`--ref` 可指定提交，`--identity` 可选择操作者私钥。工具只归档所选提交在本机构建，不读取本地 `.env`。测试在本机临时容器、网络和数据库中运行，通过后本地构建镜像，再经 SSH 上传镜像与测试日志。服务器校验归档 SHA-256、架构、镜像 ID、归属和源码提交，导入镜像、备份并切换服务；不在服务器构建或安装应用依赖。首次部署在服务器生成私有配置，正式与演示数据库隔离。备份、回退条件及目标机依赖见 [运维说明](../.agents/skills/goal-together-release/references/operations.md)。

## 镜像清理

服务器按 50GB 小盘预算维护。每次发布通过隔离测试、备份及本机和 HTTPS 验证后，默认 `keep_images=1`，保留当前成功版本和所有现存容器引用的镜像；不再常驻保留三个成功版本。开发机 `.data/releases/<发布号>/image.tar` 与 `source.json` 持久保存回滚镜像、哈希及身份。上一版缺少站外归档记录时暂保留并报告 `recovery_archive_pending`，补齐可验证制品后再清理。只逐个删除带本项目归属标签的旧应用镜像，不强制删除，不执行全局清理，不删除数据库、卷或备份。清理失败单独记入发布回执，应用发布状态不因此变成失败；有跳过项、缺少恢复归档或清理错误时，空间维护仍有待办；可重试：

```sh
python3 .agents/skills/goal-together-release/scripts/release.py cleanup --execute
```

共享构建缓存、基础镜像、无标签镜像和其他项目不在清理范围；停止容器需另按整机维护流程检查后清理，不能将本功能视为全服务器磁盘清理。每次删除前重查容器引用和标签 ID，不强删。发布锁只互斥本工具的服务器发布/清理，上传及其他 Agent 操作需另外协调。静态 4GiB 预检门槛不代表上传、解包、导入和备份的峰值空间充足，发布前还需估算。
