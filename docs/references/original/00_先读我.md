# 锅气目标台：研发交付包

这份交付包写给负责真正开发的研发人员或研发智能体。你要做的事情只有一件：把「页面演示」变成一个能真实使用的网页系统，让公司全员录入目标进展，让负责人看到总览、下钻、预警和跨月追踪。

## 一、先弄清楚现在有什么、没有什么

| 已经有 | 没有 |
|---|---|
| 一个可以点的页面演示（纯前端，双击 `页面Demo/index.html` 就能打开） | 后端、数据库、真实登录、服务端权限 |
| 全部页面的版式、文案、交互和边界处理 | 部署、域名、备份、监控 |
| 一份可运行的规则实现（`06_参考实现/rules.js`）和对应的期望结果 | 与飞书、企业微信等外部系统的对接 |
| 十二月真实目标拆分的种子数据 | 真实业绩数据（要等上线后由大家填） |

页面演示里的数据全是虚构的，存在浏览器本地存储里，换一台电脑就看不到。它的价值是：**让你一眼看懂每个页面长什么样、点了会发生什么、规则怎么算**。正式系统要让每个人在自己的设备上登录，数据放在服务器上。

## 二、产品一句话

公司只盯三个数：GMV、浪花收入、管理咨询收入。每个月，管理员把每个数拆给具体的人（谁、在哪条业务线、认领多少）。每个人每周日花一分钟，填一个数字：这一周完成了多少。系统自动算出完成度、对比时间进度、判断健康与否，并给负责人看总览、下钻、预警和跨月趋势。

设计上的三条铁律，请研发不要破坏：

1. **填报只有一个必填数字。** 风险一句话、顺带记的数都是选填。任何会让填报变慢的改动，都要先问产品。
2. **一个页面只讲一件事。** 总览只看三张卡；点进去看业务线；再点进去看人。不要为了「信息完整」把页面做厚。
3. **信息隔离在服务端做。** 成员只能看到自己的，业务线负责人只能看到自己业务线的，管理员看全部。前端隐藏不算隔离。

## 三、建议的阅读顺序

1. 先双击打开 `页面Demo/index.html`，选「公司负责人」进去点一圈，再选「TOKEN负责人」填一笔，再选「品牌负责人」看业务线视角。点页面左下角（手机上是右上角）的身份按钮，会弹出「演示控制」，可以把「今天」切到 12/02、12/15、12/31、1/05，看看提示怎么变，也可以在这里切换身份或重置数据。约十五分钟。
2. `01_产品需求.md`：页面清单、权限、交互、文案。
3. `02_业务规则.md`：所有计算口径与边界情况。**这是最容易做错的部分。**
4. `03_数据与接口/`：数据模型、接口清单、种子数据。
5. `04_验收用例.md`：怎样证明你做对了。
6. `05_待确认事项.md`：还没拍板的口径，开发时请做成可配置，别写死。
7. `05_设计文件/`：两份设计表格和方案报告，用来理解业务背景和字段来历。
8. `06_参考实现/`：规则的可执行版本，以及用它算出的期望结果。

## 五、技术选型：不限定

这份交付包不规定技术栈，由研发按团队熟悉的来选。只提几条约束：

- **前端**：演示是原生写法，没有框架，页面少、逻辑简单。可以直接沿用，也可以用任何框架重写，但视觉和文案请保持一致。手机优先：底部标签栏，电脑上变成左侧导航；填报弹层在手机上是底部抽屉，电脑上是居中浮层。
- **后端和数据库**：数据量很小（约三十人、每月几十条目标、每周几百条填报）。单机关系数据库就足够，不需要消息队列、缓存或微服务。
- **规则实现**：必须在服务端计算并与 `06_参考实现/期望结果.json` 对上。前端展示用服务端返回的结果，不要在前端再算一遍。
- **登录**：姓名加密码，或管理员发邀请链接、成员自己设密码。不要接入第三方账号体系；密码要做加盐哈希；会话用服务端会话加 HttpOnly 的 Cookie。
- **部署**：本交付包不涉及上线。不使用 Manus 托管服务，也不要求用它的账号登录。部署、域名、备份、监控，由研发另行安排。

## 六、需要研发特别注意的几件事

1. **规则里的日期全部用「年-月-日」字符串，按日历日计算，不带时区。** 演示里用协调世界时做加减，是为了避开夏令时和时区带来的差一天。正式系统请统一用「公司所在地的日历日」，所有「今天」都由服务端给出。
2. **金额是「这一周新增」，不是累计。** 累计由系统加出来。填错了用「撤销」或填负数冲减，不要提供「改累计」的入口。
3. **同一笔钱只算在一个人名下。** 主责写总数，协同的人只写自己那部分。系统要检查「分给每个人的合计」和「公司目标」是否一致，不一致只提示，不阻止。
4. **三类目标永不相加。** GMV、浪花收入、管理咨询收入各自汇总，任何页面都不要出现「总计」把它们加在一起。
5. **目标类型和目标值必须能在工作台里自由改。** 这是用户的明确要求。不要把三个类型写死在代码里。演示里已经实现：新增类型、改名、改单位、停用、排序、改每个人的目标数字（改完自动保存，并给「撤销」）。
6. **所有文案用中文。** 不要出现英文标签。「投放消耗」不要作为单独的指标或栏目展示，只能作为其他指标的背景说明出现。
7. **花名册里的敏感字段一律不要导入。** 本交付包的种子数据只含姓名和部门。

## 七、验收方式

用 `06_参考实现/基准数据_演示.json` 作为输入，把「今天」设为 2026-12-22，你的服务端算出的结果必须和 `06_参考实现/期望结果.json` 逐项一致。`04_验收用例.md` 里把关键数字列成了表，方便人工核对。

## 八、遇到不清楚的地方

先查 `02_业务规则.md` 和 `06_参考实现/rules.js`；规则文档与代码冲突时，**以代码为准**，同时把冲突记下来反馈给产品。口径类问题（什么算有效 GMV、阈值取多少），先看 `05_待确认事项.md`，里面已有建议值，开发时按建议值做成可配置项。
