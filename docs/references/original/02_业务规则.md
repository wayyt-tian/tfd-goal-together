# 业务规则与计算口径

**规则以 `06_参考实现/rules.js` 为准。** 本文用文字说明它做了什么，以及为什么这样做。文字与代码冲突时，以代码为准，并请反馈给产品。每一条都配了「例子」，对应 `06_参考实现/期望结果.json` 里的数字。

## 一、几个基本约定

1. **日期**用「年-月-日」的字符串，按日历日计算，不带时刻。月份用「年-月」，例如 `2026-12`。
2. **金额**的单位由目标类型决定，默认万元。数据库里存数字，不存带单位的字符串。
3. **「今天」由服务端给出**，用公司所在地的日历日。演示里允许手动改「今天」，正式版不提供这个入口，但服务端的计算函数要接收「今天」作为参数，这样测试才方便。
4. **三类目标永不相加。** GMV、浪花收入、管理咨询收入各算各的。新增的类型同理。
5. **填报是「增量」**：每条记录是「这一周新增了多少」。累计 = 到统计截止日为止、没有被作废的所有记录之和。负数用来冲减。
6. 一条目标 = **一个月、一个负责人、一个类型、一条业务线、一个项目** 的唯一组合。同一笔钱只算在一个人名下：主责写总数，协同的人只写自己那部分。

## 二、规则参数（工作台「规则」页，全部可改）

| 参数 | 默认 | 含义 |
|---|---|---|
| 健康线 `health_line` | 落后 5 个百分点 | 完成度不比时间进度落后超过这个数，算健康 |
| 预警线 `warn_line` | 落后 15 个百分点 | 落后超过这个数，红；介于两线之间，黄 |
| 月初观察期 `obs_days` | 3 天 | 本月已过天数不超过它，先不判灯 |
| 断更 `stale_days` | 10 天 | 距今天已有这么多天没有任何填报，算断更 |
| 连续落后 `lag_count` | 3 次 | 连续这么多个检查点都落后 |
| 低效月线 `low_line` | 70% | 一个已结月的最终完成度低于它，记一次低效月 |
| 持续低效 `low_months` | 2 次 | 近三个已结月里达到这么多次，判持续低效 |
| 统计截止 `cutoff` | 每周日 | 「每周日」或「每天」 |
| 成员可看公司总进度 `visibility` | 不能 | 「不能」或「能」 |

内部存法：`health_line` 与 `warn_line` 存成负小数（-0.05、-0.15），页面上显示成正的「个点」。`low_line` 存成小数（0.7），页面显示成百分数。

这些都是**建议值**，先用两个月再按实际调整，见 `05_待确认事项.md`。

## 三、统计截止日 `asOf(月份, 今天, 模式)`

管理者每周一看到的数，应当是同一个口径，所以默认统计到**最近的周日**，而不是今天。

- 月份早于「今天」所在月：统计截止 = 该月最后一天。
- 月份晚于「今天」所在月：统计截止 = 该月第一天的前一天（没有任何已过天数）。
- 本月：
  - 模式「每周日」：今天往前推到最近的周日（今天是周日就是今天）。
  - 模式「每天」：今天。
  - 若算出来早于月初，取月初；若晚于月末，取月末。

例子（期望结果里有完整表）：

| 月份 | 今天 | 模式 | 统计截止 |
|---|---|---|---|
| 2026-12 | 2026-12-22（周二） | 每周日 | 2026-12-20 |
| 2026-12 | 2026-12-22 | 每天 | 2026-12-22 |
| 2026-12 | 2026-12-02（周三） | 每周日 | 2026-12-01（周日在上个月，取月初） |
| 2026-12 | 2026-12-31 | 每周日 | 2026-12-27 |
| 2026-11 | 2026-12-22 | 每周日 | 2026-11-30（已结月，取月末） |
| 2027-01 | 2026-12-22 | 每周日 | 2026-12-31（未开始） |

## 四、时间进度

```
已过天数   = 统计截止日 - 月初 + 1（不小于 0，不大于本月天数）
本月天数   = 该月实际天数
时间进度   = 已过天数 / 本月天数
```

例：2026-12，统计截止 12-20，已过 20 天，本月 31 天，时间进度 = 20/31 = 64.52%。

已结月的时间进度是 100%；未开始的月是 0%。

## 五、完成度、偏差与状态

```
累计     = 到统计截止日为止，没有被作废的所有记录之和
完成度   = 累计 / 目标        （目标 ≤ 0 时为「无」）
偏差     = 完成度 - 时间进度   （百分点）
```

状态（`statusOf`）按下面顺序判断：

1. 目标不大于 0 → **未设目标**
2. 时间进度不大于 0 → **未开始**
3. 时间进度小于 1 且 已过天数 ≤ 观察期天数 → **观察期**
4. 偏差 ≥ 健康线（-5 个点）→ **健康**
5. 偏差 ≥ 预警线（-15 个点）→ **关注**
6. 否则 → **预警**

**边界：偏差正好等于阈值，算「达到」。** 因为浮点数的误差，必须用容差比较，参考实现里是 `ge(a, b) = a - b > -1e-9`。例如完成度 59.52%、时间进度 64.52%，偏差 -5.00 个点，算「健康」而不是「关注」。其他语言实现时，**建议先把比例四舍五入到四位小数再比较**，或用十进制数类型。

判灯用例（时间进度 64.52%，已过 20 天；完整表见 `期望结果.json` 的「判灯」）：

| 目标 | 完成度 | 状态 |
|---|---|---|
| 250 | 65.8% | 健康 |
| 100 | 36.9% | 预警 |
| 100 | 50.0% | 关注 |
| 100 | 59.52% | 健康（偏差正好 -5.00） |
| 100 | 49.52% | 关注（偏差正好 -15.00） |
| 100 | 49.51% | 预警 |
| 0 | — | 未设目标 |

观察期用例：目标 100、完成度 60%、已过 3 天 → 观察期；已过 4 天 → 按偏差判。

## 六、检查点 `checkpoints(月份)`

用来判断「连续落后」。取本月的**前四个周日**，加上**月末**。若第一个周日距离月初不足 3 天（含月初那天，即该周日是 1 号或 2 号），这个周日跳过，顺延。月末若已是前四个周日之一，不重复加。

| 月份 | 检查点 |
|---|---|
| 2026-12 | 12-06、12-13、12-20、12-27、12-31 |
| 2026-11 | 11-08、11-15、11-22、11-29、11-30 |
| 2027-01 | 01-03、01-10、01-17、01-24、01-31 |
| 2027-02 | 02-07、02-14、02-21、02-28（月末本身就是第四个周日，不重复） |
| 2026-05 | 05-03、05-10、05-17、05-24、05-31 |

注意 2026-11：11-01 是周日，距月初只有 1 天，被跳过。

只有**不晚于统计截止日**的检查点才参与判断。2026-12 在统计截止 12-20 时，参与的是 12-06、12-13、12-20 三个。

## 七、连续落后

对每个已到的检查点，算 **偏差 = 到该检查点的累计 / 目标 - 该检查点的时间进度**。从最近的检查点往前数，**连续有多少个偏差小于健康线**（-5 个点，用容差比较），就是「连续落后次数」。中间只要有一个没落后，就断开。

达到 3 次（`lag_count`）→ 原因里加「连续N次检查点落后」，灯提到**红**。

例（期望结果里，TOKEN负责人的 GMV 目标）：检查点偏差里最近两次落后，连续落后 2 次，不提示；BPO负责人在花芊调KOC 的协同目标，连续三次落后，提示。

## 八、持续低效

针对每一条目标的「人 + 业务线 + 类型 + 项目」组合，看**本月之前最近三个已结月**（本月和未来月不算）。每个已结月，把该组合在该月的目标合计、累计合计（到月末为止，不含作废）算出最终完成度。完成度低于「低效月线」（70%，用容差比较）算一个**低效月**。没有目标的月份不算。低效月数达到 2（`low_months`）→ 判**持续低效**。

- 原因里加「近几个月持续低效」，灯提到**红**。
- 这里是按「同一个人在同一条业务线同一个项目」跨月聚合，所以换了业务线或项目，历史不带过去。人离职、目标转给接手人后，接手人从零开始算（历史月份保留原样，不会改写）。

「趋势」页里的「持续低效」是另一个口径，针对**业务线**或**人**这一行：最近三个已结月里，有 2 个月完成度低于 70%，则标记。注意这个与目标行上的口径略不同——趋势页是按「行」合计（一个人在所有项目的合计），目标行是按「组合」。**两处都要实现**，不要合并。

## 九、断更

```
最近填报日 = 该目标最近一条没作废的记录的日期（没有则为空）
距今天数   = 今天 - 最近填报日；没有记录时 = 今天 - 月初 + 1
断更       = 目标 > 0 且 时间进度 > 0 且 时间进度 < 1 且 距今天数 ≥ 断更天数（10）
```

断更给原因加「已N天没有填报」，灯提到至少**黄**。

注意：这里用的是**今天**而不是统计截止日，因为断更是在问「多久没人管了」。默认 10 天，是给周日填报留两三天宽限。

## 十、待填（这周还没填）

用来在填报页和关注页提醒。**待填 ≠ 断更**，待填更早、更轻。

```
应填日 = dueDate(月份, 今天)
```

- 本月：今天往前推到最近的周日；若这个周日距月初不足 3 天（含当天），**还没到期**，返回「无」。
- 上个月：仅当「今天」距上月月末不超过 10 天时，应填日 = 上月月末（做月末结算）；否则「无」。
- 未来月：「无」。

```
待填 = 目标 > 0 且 应填日不为空 且 （最近填报日为空 或 最近填报日 < 应填日）
```

例（2026-12）：

| 今天 | 应填日 |
|---|---|
| 12-22（周二） | 12-20 |
| 12-02（周三） | 无（12-01 距月初不足 3 天） |
| 12-06（周日） | 12-06 |
| 12-07（周一） | 12-06 |
| 12-31（周四） | 12-27 |
| 次年 01-05 | 12-31（上月月末结算，距月末 5 天） |
| 次年 01-11 | 无（距月末 11 天，超过 10 天） |

## 十一、灯（level）与原因

一条目标最终显示的「灯」和「原因」：

```
原因  = [ 状态为预警 → "进度落后较多" ]
      或 [ 状态为关注 → "进度略慢" ]
      + [ 连续落后 ≥ 3 → "连续N次检查点落后" ]
      + [ 持续低效     → "近几个月持续低效" ]
      + [ 断更         → "已N天没有填报" ]
需要关注 = 原因不为空

灯 = 红，  若 状态=预警 或 连续落后≥3 或 持续低效
   黄，  否则若 状态=关注 或 断更
   绿，  否则若 状态=健康
   灰，  其他（观察期、未开始、未设目标）
```

「关注」页和总览的红色提示条，统计的是「需要关注 且 灯不是灰」的目标行。观察期、未开始、未设目标的行灯是灰，不会出现在里面。断更的行灯至少是黄，所以会出现。

## 十二、聚合（总览、类型页、业务线页的合计）

对一组目标行：

```
目标   = 各行目标之和；若传入「公司月目标」，则用公司月目标代替（只有管理员的总览与类型页用）
累计   = 各行累计之和
完成度 = 累计 / 目标
偏差   = 完成度 - 时间进度
状态、灯 = 按第五节同一套规则判断（用聚合后的完成度）
需关注数 = 各行里「需要关注」的行数
预计月末 = 完成度 / 时间进度（时间进度 > 0 且不在观察期时）
已分配  = 各行目标之和（始终是各行之和，用来和公司月目标比较）
```

注意：聚合的灯**只看状态**（预警红、关注黄、健康绿、其他灰），不会因为其中某一行持续低效就变红。「需要关注的行」在卡片上单独以「N 项需要关注」显示。

「预计月末」是**线性外推**，只是个参考，卡片上写的是「照现在的节奏，月末约 96%」，措辞要保持「约」。

## 十三、跨月趋势 `trend(类型, 按业务线或按人, 月数=6)`

取含本月在内的最近 6 个月。对每一行（业务线或人）、每个月，把该类型下所有目标行的「目标」「累计」加起来，得到完成度。

- 单元格颜色（已结月）：完成度 ≥ 95%（即 1 + 健康线）绿；≥ 70% 黄；< 70% 红；没有目标灰。
- 单元格颜色（本月）：按偏差，同第五节，且打上「未结束」标记（虚线框）。
- 行标记「持续低效」：该行最近三个已结月里，低于 70% 的月数 ≥ 2。
- 排序：持续低效的在前，其余按名称。
- 最后一行「合计」：各列把所有行的目标与累计相加再算。
- 业务线负责人看趋势时，只统计自己业务线的行。

## 十四、月度完成度（已结月）`monthDone`

给「前几个月的完成度」和持续低效使用。取某人、某业务线、某类型、某项目在该月的所有有效目标，目标求和、累计求和（到月末）。若没有目标，完成度为「无」（不是 0）。

## 十五、边界情况清单

| 情况 | 期望行为 |
|---|---|
| 目标 = 0 | 状态「未设目标」，填报页不给按钮；不计入连续落后、断更、待填 |
| 月初前 3 天 | 状态「观察期」，不判灯；仍可填报；断更不判（时间进度小于 1 且大于 0 才判，月初已过 1 到 3 天时不会达到 10 天） |
| 月末最后一天 | 时间进度 = 100%；完成度低于 85% 就是预警 |
| 本月没有任何记录 | 累计 0、完成度 0%；距今天数 = 今天 - 月初 + 1；时间进度超过 3 天且偏差超过阈值，亮红 |
| 填负数 | 允许，用于更正；累计可以暂时为负，但提示「负数表示冲减」 |
| 撤销记录 | 记录标「作废」，不计入任何累计、检查点、断更；可以恢复 |
| 同一天多条记录 | 全部累加；最近填报日取最大的日期 |
| 填报日期晚于统计截止日（例如周三填了「今天」） | 不计入本期累计（累计到统计截止日），但「最近填报日」和「距今天数」要算它 |
| 填报日期不在本月 | 不允许。弹层的日期选择限制在本月，且不晚于今天 |
| 目标改动 | 立即影响本月所有计算；之前的月份不动。每次改动写修改记录 |
| 人员停用 | 本月及以后的目标转给接手人；历史目标与历史填报**保持原作者** |
| 业务线或类型被隐藏 | 页面不显示，历史数据保留；再显示后恢复 |
| 新增类型 | 总览自动多一张卡；公司月目标可以不设（则卡片用各行之和做目标） |
| 公司月目标与分配合计不等 | 只提示，不阻止 |
| 未来月份 | 只在工作台目标页可以进入（最多本月加两个月），其他页面不允许 |
| 目标改到小于已完成 | 允许，完成度超过 100% 正常显示 |
| 一个人同时是业务线负责人和成员 | 「填报」页永远显示他自己的全部目标；「总览、关注、趋势、角标」只按他负责的业务线统计，不并入他自己在别的业务线上的目标。他自己的目标仍然可以点开看详情 |

## 十六、金额与数字的显示

- 金额：最多保留一位小数（千位分隔符用逗号），内部计算保留两位。
- 百分比：整数，四舍五入。
- 偏差：「比时间进度快 5 个点」或「慢 5 个点」。
- 「—」表示没有值（比如没有目标）。
