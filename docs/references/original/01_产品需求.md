# 产品需求与信息架构

本文件说明「锅气目标台」每个页面是什么、给谁看、点了会怎样。所有页面都能在 `页面Demo/index.html` 里点出来，截图在 `07_截图/`。

## 一、背景与要解决的问题

锅气家族约三十人，分布在郑州、大连、佛山、北京，主营国内电商：自有品牌，也帮其他品牌做 GMV 的交付与增长；另有研发、工具和人工智能团队，对内对外提供工具与方案。

管理上的痛点：公司负责人和各业务线负责人，没有一套清晰的体系，看到「目标完成到哪了」「是否按时间进度健康」「谁长期落后」。之前用表格，但表格太密、没法隔离信息、不能开放给所有人。

因此需要一个网页平台，满足四件事：

1. 所有人都能录入自己的进展，**录入极简**。
2. 公司负责人和业务线负责人能看到**总览**，并能**按业务线、按人下钻**。
3. 能**提前预警**进度风险，能识别**跨月持续偏差大**的人或业务。
4. **目标类型和目标值，管理员可以在工作台里随时自由调整。**

## 二、三类角色与隔离

| 角色 | 谁 | 看得到什么 | 能做什么 |
|---|---|---|---|
| 成员 | 默认所有人 | 只有自己的目标、自己的填报、自己的记录 | 填报、撤销自己的记录 |
| 业务线负责人 | 被管理员设为某条业务线负责人的成员 | 自己业务线里所有人的目标与进展；另外在填报页看到自己的全部目标 | 与成员相同，另可看总览、关注、趋势（范围限于自己的业务线） |
| 管理员 | 公司负责人及管理员指定的人 | 全公司 | 以上全部，另可进入工作台改目标、人员、类型、业务线、规则 |

补充规则：

- 角色不是单独存的一列「业务线负责人」，而是由 `业务线.负责人` 推出来：谁是某条业务线的负责人，谁就拥有该业务线的查看范围。一个人可以负责多条业务线。
- 设置项「成员能看公司总进度吗」默认「不能」。打开后，成员能看到公司和各类型的合计卡片，但**看不到别人的明细**，也不能下钻。
- 至少保留一位管理员，停用最后一位管理员时要拦住。
- 一切权限在服务端判断。前端只负责不显示，不负责保证。

### 权限矩阵

| 页面或操作 | 成员 | 业务线负责人 | 管理员 |
|---|---|---|---|
| 填报页：看自己的目标卡片 | 是 | 是 | 是 |
| 填报：对自己的目标新增记录 | 是 | 是 | 是 |
| 撤销、恢复记录 | 仅自己写的 | 仅自己写的 | 全部 |
| 我的记录 | 是 | 是 | 是 |
| 总览 | 只在「成员能看公司总进度」打开时，且只看合计卡 | 自己业务线范围 | 全公司 |
| 类型页、业务线页、人页、目标详情 | 否（只能看自己的目标详情） | 自己业务线范围 | 全公司 |
| 关注 | 否 | 自己业务线范围 | 全公司 |
| 趋势 | 同「总览」 | 自己业务线范围 | 全公司 |
| 工作台（目标、成员、类型与业务线、规则、修改记录） | 否 | 否 | 是 |

访问范围之外的页面地址，应当回到该角色的首页，而不是显示「无权限」，避免暴露「这里有东西」。演示里就是这样处理的。

## 三、信息架构

```
登录
├─ 填报            （所有人的首页或第二页）
│    └─ 填报弹层    （一个数字）
├─ 总览            （业务线负责人和管理员的首页）
│    └─ 目标类型页  → 业务线页 → 人页 / 单个目标详情
├─ 关注            （业务线负责人、管理员）
├─ 趋势            （业务线负责人、管理员；成员无此项，改显示「记录」）
├─ 记录            （成员的第三个标签：我填过的）
└─ 工作台          （仅管理员）
     目标 · 成员 · 类型与业务线 · 规则 · 修改记录
```

导航：手机上是底部标签栏；宽度不小于 900 像素时变成左侧竖向导航。标签是否出现，取决于角色，见演示 `U.tabs()`。

下钻最多三步：总览 → 类型 → 业务线 → 单个目标。其中「类型」「业务线」是分别一页，不是树形展开。每页顶部有面包屑，可以回退。

## 四、页面清单

### 1. 登录

- 正式版：姓名加密码。管理员在「成员」里添加人后，系统生成**邀请链接**，对方打开自己设密码。忘记密码由管理员重置，重置后重新生成邀请链接。
- 演示版：不需要密码，直接点身份进入。页面里有一句灰色说明，**正式版不要保留这句，也不要保留「选身份」的列表。**
- 登录后，业务线负责人和管理员进「总览」，成员进「填报」。

### 2. 填报（成员最常用的页面）

目的：让每个人在一分钟内，把本周的数字填上。

页面内容：

- 标题：「某某，本周填报」，下面一行：「统计到 12月20日（周日） · 你负责 3 项目标」。
- 提示条：有待填项时「你有 N 项这周还没填，每项只要一个数字。」；都填好了「这周都填好了，谢谢。」
- 每个目标一张卡片：业务线与项目名、类型与岗位目标说明、累计与目标、完成百分比、带「时间进度竖线」的进度条、「这周还没填」或「已填」、上次填报日期、一个大按钮「填这一周」或「再补一笔」。
- 目标为 0 的，不给按钮，显示「目标是 0，暂时不用填。」
- 月初前十天，若上个月最后一个检查点还没填，在最上面多出一组「上月月末结算」。
- 页脚：「看我填过的记录」。

### 3. 填报弹层

手机上是底部抽屉，电脑上是居中浮层。字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| 这一周完成了多少（单位） | 是 | 一个大号数字输入框，打开即聚焦。填的是**这一周新增**，系统自动加进累计。输入时实时提示「提交后累计 X / 目标（Y%）」。可以填负数，用来冲减填多了的。 |
| 有什么风险或需要帮忙 | 否 | 一句话，最多八十个字。 |
| 领先指标（名称由目标设置，如「直播场次」） | 否 | 只有目标里设置了才出现。 |
| 统计到哪天 | 默认 | 默认是最近的周日（或今天），可点「改日期」换；不能晚于今天，不能早于本月一号。 |
| 按钮 | | 「这周没有，记 0」直接提交零；「提交」在没填数字时是灰的。 |

提交后：关闭弹层、卡片立刻更新、底部出现提示「已记下：某业务线 +8.5 万元」，带「撤销」。几秒后提示消失，之后仍可在「我的记录」里撤销。

**不要在输入框里放占位文字。** 示例和说明放在标签下方，原因是占位文字一输入就消失，且容易被当成已填的值。

### 4. 我的记录

按日期倒序，最多显示最近四十条：业务线、日期、类型、风险、金额、「撤销」或「恢复」。被撤销的记录用删除线显示，不计入统计。

### 5. 总览

目的：十秒内知道公司整体是否健康，有几件事要看。

- 标题：管理员「全公司目标总览」；业务线负责人「我负责的业务线」，副标题写上业务线名。
- 一行说明：「数据统计到 12月20日（每周日截止）」。
- 月份切换：只能往前，不能进入未来月份。
- 红色提示条：「N 项需要关注 去看看」，点进「关注」页。没有就不显示。
- 三张卡片，每个目标类型一张：类型名、状态标签（健康、关注、预警，或「观察期」「未设目标」）、大号「已完成 / 目标 单位」、进度条（带时间进度竖线）、「已完成 62%　时间进度 65%」、「照现在的节奏，月末约 96%」、「2 项需要关注」。
- 卡片的目标数：管理员看到的是**公司月目标**（若设置了），业务线负责人看到的是**自己业务线合计**。
- 公司月目标与分配合计不等时，卡片上用黄字提示「还有 X 没分下去」或「分下去的比公司目标多 X」。
- 底部：「本周还有 N 项没填报。」（仅当月、仅业务线负责人和管理员）。
- 新增的目标类型，自动多一张卡片。业务线负责人只看到自己业务线里出现过的类型。

### 6. 目标类型页（点总览卡片进入）

- 顶部一张合计卡，下面是按业务线的列表，每行：业务线名、人数、进度条、「完成 / 目标」、完成百分比、状态标签、需关注的项数。
- 排序：先红灯、再黄灯、再绿灯，同色按目标大小倒序。

### 7. 业务线页

- 合计卡 + 每个人一行：头像字、姓名、主责或协同标签、项目名、进度条、完成与目标、第一条预警原因、百分比、状态。
- 点一行进入单个目标详情。

### 8. 单个目标详情

- 姓名、角色、状态；一行描述「业务线 · 类型 · 月份 · 岗位目标说明」。
- 大卡：累计与目标、进度条、三个数字（已完成、时间进度、预计月末）、预警原因标签、最近一条风险原话。
- 「每周检查点」：本月已到的每个周日一个彩色圆点；下面是前三个已结月的完成度小标签。
- 统计口径：目标上写的口径提醒。
- 链接「看某某的全部目标」。
- 填报记录：最近十二条，日期、金额、风险；有权限的人有「撤销」。
- 管理员另有按钮「调整这条目标」。

### 9. 人页

某个人本月认领的所有目标，每条一行。从业务线页或目标详情的链接进入。

### 10. 关注

只列需要看一眼的事，不是全量报表。

- 顶部说明：「只列出落后的、持续低效的、很久没填的。其余都在正常范围内。」
- 每项一张卡：姓名 · 业务线、类型与角色、完成百分比、与时间进度的差距、进度条、原因标签、最近一条风险。排序：红先于黄，同色按落后最多的在前。
- 没有时显示「目前没有需要特别关注的。大家都在节奏上。」
- 下面另一组：「这周还没填（N）」，列出待填但没有预警的人，点进目标详情。

### 11. 趋势

- 顶部两个切换：类型（所有启用的类型）、「按业务线 / 按人」（业务线负责人只能按业务线与本线人员）。
- 一张「最近六个月完成度」热力表，行是业务线或人，列是月份，最后一行「合计」。
- 颜色：已结月按最终完成度：不低于 95% 绿、70% 到 95% 黄、低于 70% 红、没有目标灰；本月用虚线框，按时间进度判色，因为还没走完。
- 持续低效的行，名字下面带红色标签「持续低效」，表头上方给一条提示：「某某 近几个月反复没达到，建议当面聊一次，看是目标定得不合适，还是需要支持。」
- 说明：「本月那一格按时间进度判颜色。」鼠标悬停每格显示「完成 / 目标」。

### 12. 工作台（管理员）

顶部五个标签：目标、成员、类型与业务线、规则、修改记录。

**目标**

- 月份切换：可以往后看到本月加两个月，用来提前排下个月、下下个月的目标。
- 类型切换：每个启用的类型一个按钮。
- 「公司目标」卡：一个大号数字输入框，旁边一个提示标签（已全部分完、还有 X 没分下去、多分了 X、未设公司目标），右边「已分配 N」。
- 「分配给每个人」：按业务线分组，每组标题带小计；每行：姓名、主责或协同标签、项目、岗位目标说明、**一个可以直接改的数字框（改完离开输入框就自动保存，底部出现「目标 250 → 260　撤销」）**、「编辑」按钮。
- 数字框要求不小于零；填错了恢复旧值并提示「请填大于等于 0 的数字」。
- 按钮「＋ 新增一条目标」。表单字段：负责人、目标类型、角色、业务线、项目（选填，不填记作「整体」）、目标数字、岗位目标说明（选填）、统计口径提醒（选填）、每周顺带记的数（选填）。同一人、同一类型、同一业务线、同一项目、同一个月只能有一条，重复时提示「这个人在这条业务线、这个项目上已经有目标了，请直接改那一条」。
- 编辑目标：类型不能改（改类型等于新建一条），其余都能改；有「删除」按钮，删除前确认；若已有填报，提示「删除后不再计入统计，如果只是想停掉，把目标改成 0 就行」。
- 新的一个月没有目标、而上个月有时，顶部出现黄条：「某月还没有目标，可以直接沿用上个月的。 复制上月目标」。复制时跳过已停用的成员，并带上上月的公司目标。

**成员**

- 列表：头像字、姓名、部门、角色标签与状态（已激活、还没设置密码、已停用）。
- 「添加成员」：姓名、部门（可输入，也可从已有部门里选）。
- 「批量添加」：一行一个人，姓名和部门用空格、逗号或顿号隔开。重名的跳过并汇总提示。
- 点一个人：改姓名、部门、权限（成员或管理员）；若他是某条业务线的负责人，会提示。
- 「停用」：先检查是不是最后一位管理员；若他还有本月及以后的目标，要求选「谁来接手」，这些目标自动转给接手人，他负责的业务线也转给接手人；历史月份和历史填报**保持原样**。若接手人在同一个月、同一类型、同一业务线、同一项目上已经有目标，会重复，此时**整体拒绝、什么都不改**，并提示「某某在某月已经有『业务线 · 类型』的目标，请换一位接手人」，由管理员换人或先把那条目标合并。
- 已停用的人可以「重新启用」。

**类型与业务线**

- 目标类型列表：名称、单位、启用或隐藏；上移、下移、编辑。
- 「新增目标类型」：名称（必填，不能重名）、单位（输入，或点常用单位：万元、元、个、条、场、人、次）。
- 编辑类型：改名、改单位、「在页面上显示」开关。隐藏后不再出现在填报、总览、趋势，历史数据保留。
- 提示：「类型想加就加，例如「签约客户数」「新品上线数」。不同类型不会加在一起。」
- 业务线列表：名称、负责人、上移、下移、编辑。
- 编辑业务线：名称、负责人（选填）、显示开关。说明：负责人可以看到这条业务线里所有人的进展，看不到其他业务线。

**规则**

九个参数，见 `02_业务规则.md` 第二节。每个都是一个小数字框或下拉，改完即生效并出提示「规则已更新」。底部「恢复建议值」。

**修改记录**

最近六十条，每条：一句话说明改了什么、谁改的、什么时候。涵盖：目标改动、公司目标改动、增删成员、改类型与业务线、改规则、复制上月目标。一句话示例：「品牌负责人 · 锅气玛特自营 · GMV：目标 250 → 260」。

## 五、状态与颜色

| 状态 | 含义 | 颜色 |
|---|---|---|
| 健康 | 完成度不比时间进度落后超过 5 个百分点 | 绿 |
| 关注 | 落后 5 到 15 个点 | 黄 |
| 预警 | 落后超过 15 个点 | 红 |
| 观察期 | 本月前 3 天，数据太少，不判 | 灰 |
| 未开始 | 本月统计还没开始 | 灰 |
| 未设目标 | 目标为 0 或没设 | 灰 |

页面上的「灯」（红黄绿灰）比状态多考虑两件事：连续落后和持续低效会把灯提到红；断更会把灯提到至少黄。见业务规则。

每个状态标签都要有文字，**不能只靠颜色**，考虑色弱用户。

## 六、文案与语气

- 全部中文。不出现英文标签。允许的外文缩写只有 GMV。
- 对成员的语气温和：「谢谢」「没有就空着」「填错了就撤销」。
- 对管理者的预警措辞克制，给出可操作的建议，而不是评判：「建议当面聊一次，看是目标定得不合适，还是需要支持」。
- 不使用「绩效」「考核」「扣分」「排名」这类词。这个系统的定位是看进展、早发现，不是打分。
- 「投放消耗」不单独作为指标或栏目。

## 七、非功能要求

- **手机优先**：触控区域不小于 44 像素；填报在手机上单手可完成；弹层是底部抽屉。
- **性能**：约三十人规模，任何页面首屏小于一秒。不需要分页，不需要缓存层。
- **离线与网络差**：提交失败时保留已输入的内容并提示重试；不要丢失用户刚填的数字。
- **可撤销**：任何会改变数字的操作（填报、改目标、改公司目标）都有「撤销」。
- **留痕**：目标、公司目标、人员、类型、业务线、规则的每次变更，都写修改记录（谁、何时、改了什么）。填报记录保留作者与创建时间，**只做作废，不做物理删除**。
- **无障碍**：输入框都有标签；图标按钮有文字说明；进度条有文字替代，如「完成 62%，时间进度 65%」。
- **时区**：所有日期按公司所在地的日历日；服务端给「今天」。

## 八、不做什么（第一期明确不做）

- 不做审批流、不做考核打分、不做排名榜。
