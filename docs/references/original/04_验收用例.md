# 验收用例

做完以后，对照本文逐条自测。**所有数字都来自同一份基准**：`06_参考实现/基准数据_演示.json`（输入）和 `06_参考实现/期望结果.json`（输出）。把基准数据导入你的数据库，把「今天」固定成 2026-12-22，你的接口返回的数应当与下面完全一致。

## 零、怎么做对数

```
cd 06_参考实现
node 生成基准.js
```

会重新生成两个 json。重新生成的结果必须与交付的文件完全一致（交付前已核对一致）。你的实现不必用 JavaScript，但对同一份输入要算出同一份输出。比对时数字取到文中的位数：完成度四位小数，累计两位小数。

**测试时「今天」必须可以注入**。2026-12-22 是周二，所以统计截止是上一个周日 2026-12-20。

## 八、判灯的边界

时间进度 64.52%，已过 20 天，规则默认。「偏差 = 完成度 - 时间进度」，不小于 -5 个点算健康，不小于 -15 个点算关注，更落后为预警。

| 目标 | 完成度 | 已过天数 | 期望状态 | 说明 |
|---|---|---|---|---|
| 250 | 65.80% | 20 | 健康 | 领先 |
| 100 | 36.90% | 20 | 预警 | |
| 100 | 50.00% | 20 | 关注 | |
| 100 | 60.00% | 3 | 观察期 | 已过天数不超过 3，先不判灯 |
| 100 | 60.00% | 4 | 健康 | 观察期刚过 |
| 100 | 0 | 0 | 未开始 | 月度尚未开始 |
| 100 | 70.00% | 20 | 健康 | |
| 0 | 0 | 20 | 未设目标 | |
| 100 | 59.52% | 20 | 健康 | 恰好落后 5.00 个点，**含边界** |
| 100 | 49.52% | 20 | 关注 | 落后 14.99 个点 |
| 100 | 49.51% | 20 | 预警 | 落后 15.01 个点，**含边界** |
| 100 | 120.00% | 31 | 健康 | 超额 |

用例 F1：59.52% 是健康、49.52% 是关注、49.51% 是预警。这三条是**浮点数边界**：直接做 `a >= b` 在一些语言里会因为 0.1 之类的二进制误差判反。必须像 `rules.js` 里的 `ge` 一样加一个极小的容差（约 1e-9）。
