# 数据模型

数据量很小：约三十人，每月几十条目标，每周几百条填报。关系型数据库即可。下面的建表语句用通用写法，研发按所选数据库的方言调整。

## 一、实体关系

```
成员 ──< 业务线.负责人            （一个人可以负责多条业务线）
目标类型 ──< 目标 >── 业务线
成员 ──< 目标                    （负责人）
目标 ──< 填报记录 >── 成员       （作者）
目标类型 + 月份 ── 公司月目标
设置、修改记录、会话、邀请
```

## 二、表与字段

### 成员 `members`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| name | 文本，唯一 | 姓名，登录用。例如「星宇」「Kalvin.Dai」。重名时加区分，不做自动处理 |
| dept | 文本 | 部门，例如「品牌经营部」「AIGC创新部」，自由文本 |
| title | 文本 | 岗位，可空，预留 |
| role | 文本 | `admin` 或 `member` |
| active | 0 或 1 | 停用后不能登录，历史数据保留 |
| pw_hash | 文本，可空 | 密码哈希（加盐，慢哈希算法）。空表示还没设置密码 |
| created_at | 时间 | |

「业务线负责人」不存在这张表里，由 `lines.manager_id` 推出。

### 目标类型 `metrics`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| name | 文本，唯一 | 例如「GMV」「浪花收入」「管理咨询收入」，管理员可以新增 |
| unit | 文本 | 例如「万元」「个」「场」，默认「万元」 |
| sort | 整数 | 显示顺序 |
| active | 0 或 1 | 隐藏后不在填报、总览、趋势里出现，历史保留 |

### 业务线 `lines`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| name | 文本，唯一 | 例如「锅气玛特自营」 |
| manager_id | 外键→成员，可空 | 业务线负责人，可以查看这条线所有人的进展 |
| sort | 整数 | |
| active | 0 或 1 | |

### 公司月目标 `company_targets`

| 字段 | 类型 | 说明 |
|---|---|---|
| period | 文本 `YYYY-MM` | |
| metric_id | 外键→目标类型 | |
| value | 数字 | |

主键是（period, metric_id）。可以不设；不设时，总览用各目标行的合计代替。

### 目标 `goals`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| period | 文本 `YYYY-MM` | |
| metric_id | 外键→目标类型 | 创建后不可改 |
| line_id | 外键→业务线 | |
| project | 文本 | 默认「整体」。例如「短带」「自播」 |
| member_id | 外键→成员 | 负责人 |
| role | 文本 | `主责` 或 `协同` |
| duty | 文本 | 岗位目标说明，例如「锅气玛特自营渠道成交额」 |
| target | 数字 ≥ 0 | 本月目标，单位随类型 |
| lead_name | 文本 | 「每周顺带记的数」名称，如「直播场次」；空则不显示该输入框 |
| guard | 文本 | 统计口径提醒，如「按退款后口径统计」 |
| note | 文本 | 备注 |
| active | 0 或 1 | 删除即置 0，不物理删除 |

**唯一约束**（仅 active=1）：(period, member_id, metric_id, line_id, project)。

### 填报记录 `entries`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | 整数，主键 | |
| goal_id | 外键→目标 | |
| author_id | 外键→成员 | 谁填的（通常就是负责人；管理员代填时是管理员） |
| date | 日期 | 统计到哪天，必须在目标所在月内，且不晚于今天 |
| amount | 数字 | 这一周新增，可为负 |
| risk | 文本，可空 | 一句话风险，最多 80 字 |
| lead_value | 数字，可空 | 领先指标的数 |
| voided | 0 或 1 | 作废。不做物理删除 |
| created_at | 时间 | |

### 设置 `settings`

键值表。键：`health_line`、`warn_line`、`obs_days`、`stale_days`、`lag_count`、`low_line`、`low_months`、`cutoff`、`visibility`。默认值见 `02_业务规则.md` 第二节。

### 修改记录 `audit_log`

| 字段 | 说明 |
|---|---|
| id | |
| at | 时间 |
| who_id | 谁操作的 |
| text | 一句话，例如「品牌负责人 · 锅气玛特自营 · GMV：目标 250 → 260」 |
| kind | 类别：goal、company_target、member、metric、line、setting、copy_month |
| ref_id | 关联对象，可空 |

只增不改。页面只显示最近六十条，库里全留。

### 会话 `sessions`、邀请 `invites`（后端专用，演示里没有）

- `sessions`：id（随机，不可猜）、member_id、created_at、expires_at。
- `invites`：token（随机，一次性）、member_id、expires_at、used_at。管理员添加成员或重置密码时生成，有效期建议 7 天；成员打开链接设置密码后作废。

## 三、建表语句（通用写法）

```sql
CREATE TABLE members (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  dept TEXT NOT NULL DEFAULT '',
  title TEXT NOT NULL DEFAULT '',
  role TEXT NOT NULL DEFAULT 'member' CHECK (role IN ('admin','member')),
  active INTEGER NOT NULL DEFAULT 1,
  pw_hash TEXT,
  created_at TEXT NOT NULL
);

CREATE TABLE metrics (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  unit TEXT NOT NULL DEFAULT '万元',
  sort INTEGER NOT NULL DEFAULT 0,
  active INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE lines (
  id INTEGER PRIMARY KEY,
  name TEXT NOT NULL UNIQUE,
  manager_id INTEGER REFERENCES members(id),
  sort INTEGER NOT NULL DEFAULT 0,
  active INTEGER NOT NULL DEFAULT 1
);

CREATE TABLE company_targets (
  period TEXT NOT NULL,
  metric_id INTEGER NOT NULL REFERENCES metrics(id),
  value REAL NOT NULL CHECK (value >= 0),
  PRIMARY KEY (period, metric_id)
);

CREATE TABLE goals (
  id INTEGER PRIMARY KEY,
  period TEXT NOT NULL,
  metric_id INTEGER NOT NULL REFERENCES metrics(id),
  line_id INTEGER NOT NULL REFERENCES lines(id),
  project TEXT NOT NULL DEFAULT '整体',
  member_id INTEGER NOT NULL REFERENCES members(id),
  role TEXT NOT NULL DEFAULT '主责' CHECK (role IN ('主责','协同')),
  duty TEXT NOT NULL DEFAULT '',
  target REAL NOT NULL DEFAULT 0 CHECK (target >= 0),
  lead_name TEXT NOT NULL DEFAULT '',
  guard TEXT NOT NULL DEFAULT '',
  note TEXT NOT NULL DEFAULT '',
  active INTEGER NOT NULL DEFAULT 1
);
-- 只对有效目标做唯一约束（不同数据库写法不同，下面是部分索引的写法）
CREATE UNIQUE INDEX goals_unique ON goals (period, member_id, metric_id, line_id, project) WHERE active = 1;
CREATE INDEX goals_period ON goals (period, active);
CREATE INDEX goals_member ON goals (member_id, period);

CREATE TABLE entries (
  id INTEGER PRIMARY KEY,
  goal_id INTEGER NOT NULL REFERENCES goals(id),
  author_id INTEGER NOT NULL REFERENCES members(id),
  date TEXT NOT NULL,
  amount REAL NOT NULL,
  risk TEXT NOT NULL DEFAULT '',
  lead_value REAL,
  voided INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL
);
CREATE INDEX entries_goal ON entries (goal_id, voided, date);

CREATE TABLE settings (key TEXT PRIMARY KEY, value TEXT NOT NULL);

CREATE TABLE audit_log (
  id INTEGER PRIMARY KEY,
  at TEXT NOT NULL,
  who_id INTEGER REFERENCES members(id),
  kind TEXT NOT NULL,
  ref_id INTEGER,
  text TEXT NOT NULL
);
CREATE INDEX audit_at ON audit_log (at DESC);

CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  member_id INTEGER NOT NULL REFERENCES members(id),
  created_at TEXT NOT NULL,
  expires_at TEXT NOT NULL
);

CREATE TABLE invites (
  token TEXT PRIMARY KEY,
  member_id INTEGER NOT NULL REFERENCES members(id),
  expires_at TEXT NOT NULL,
  used_at TEXT
);
```

## 四、关键约束和一致性

1. **金额类字段用定点小数。** 演示里是浮点；正式库如果用 `REAL`，比较阈值时按 `02_业务规则.md` 的容差处理；更稳妥的做法是用十进制类型保留两位。
2. **月份存文本 `YYYY-MM`**，按字典序比较即可（`period < '2026-12'`）。
3. **日期存文本 `YYYY-MM-DD`**，同理。避免用带时区的时间戳存业务日期。
4. **不物理删除**：目标置 `active=0`；填报置 `voided=1`；成员置 `active=0`；类型、业务线置 `active=0`。
5. **目标的 `metric_id` 创建后不可改**，要换类型就新建一条。
6. **停用成员时**，在同一事务里：把本月及以后的有效目标转给接手人；把他作为负责人的业务线转给接手人；置 `active=0`；写修改记录。历史月份的目标与全部填报，保持原 `member_id`、`author_id`。
7. **接手人若已在同一业务线、同一项目、同一类型有目标**，会违反唯一约束。此时应返回明确的错误，让管理员先合并（把其中一条改为 0 或删除），而不是自动合并。
8. **复制上月目标**：只有目标月完全没有有效目标时才允许；跳过已停用的成员；同时复制公司月目标（目标月已有同类型则不覆盖）；写一条修改记录「从某月复制了 N 条目标到某月」。

## 五、与设计表格的对应关系

设计表格有两份：`锅气家族目标管理表_正式版.xlsx`（十二月真实拆分）和 `锅气家族目标管理表_演示版.xlsx`（含四个月虚构数据）。两份都是九个工作表：使用说明、总览、人员视图、月趋势、周趋势、目标表、周填报表、参数、飞书搭建指南。

「目标表」的前半是人工填写的列，后半（第 Q 列起）是公式算出来的辅助列，**辅助列不入库**，由规则计算得到。

| 表格里的位置（列名照表格原文） | 对应的数据模型 |
|---|---|
| 「目标表」每一行 | `goals` 一条 |
| 目标表 A「统计周期」，如「2026年12月」 | `goals.period`，存成 `2026-12` |
| 目标表 B「业务线」、K「项目」 | `lines.name`、`goals.project` |
| 目标表 C「目标类型」 | `metrics.name`（GMV、浪花收入、管理咨询收入） |
| 目标表 D「所属团队」 | `members.dept`（部门属于人，不属于目标行；表格里写在每行是为了筛选方便） |
| 目标表 E「岗位目标」 | `goals.duty` |
| 目标表 F「负责人」、L「角色」 | `goals.member_id`、`goals.role` |
| 目标表 G「目标（万元）」 | `goals.target` |
| 目标表 H「目标完成度」、I「风险（最新一条）」 | 不存，计算得到 |
| 目标表 J「目标代号」（G01…L07、C01…C03） | 不入库，只是表格里的内部编号，可放进 `note` 备查 |
| 目标表 M「冲刺目标（选填）」 | **平台第一期没有。** 表格里保留了一个选填的冲刺目标，平台为了简单只留一个目标数。如以后要分档，在 `goals` 加 `stretch` 字段 |
| 目标表 N「质量底线」 | `goals.guard`（页面上改叫「统计口径提醒」） |
| 目标表 O「领先指标名称」 | `goals.lead_name` |
| 目标表 P「备注」 | `goals.note` |
| 目标表 Q 之后的列（目标编号、累计完成、时间进度、进度偏差、状态、预计月末完成度、最近填报日、未更新天数、领先指标累计、连续落后周数、持续低效、预警原因） | 全部是计算结果，对应规则文档第三到十一节；平台里同名的字段在接口的响应里返回，不入库 |
| 「周填报表」每一行 | `entries` 一条。「统计到哪天（周日）」→ `date`；「我的目标（下拉选择）」→ `goal_id`；「这一周完成」→ `amount`；「风险或卡点」→ `risk`；「领先指标（选填）」→ `lead_value`；后面的目标编号、负责人、业务线、目标类型、填报检查、键 是辅助列，不入库 |
| 「参数」里「判断规则」一栏 | `settings`，名称对照见下表 |
| 「参数」里「公司月目标」 | `company_targets`，表格里每个类型一列、每个月一行，入库时拆成（月份，类型，值）三元组 |
| 「总览」「人员视图」「月趋势」「周趋势」 | 不存，由规则计算得到，见 `02_业务规则.md` |

表格「参数」与平台规则参数的对照，**有两处刻意不同**：

| 表格「参数」里的名字 | 表格默认 | 平台 `settings` 键 | 平台默认 | 说明 |
|---|---|---|---|---|
| 健康线（进度偏差不低于） | -0.05 | `health_line` | -0.05 | 一致 |
| 预警线（进度偏差低于） | -0.15 | `warn_line` | -0.15 | 一致 |
| 月初观察期（天） | 3 | `obs_days` | 3 | 一致 |
| 断更提醒（天未更新） | **7** | `stale_days` | **10** | 不同：平台给周日填报留出两三天宽限，所以放宽到 10 天。如业务希望与表格一致，改默认值即可，这是配置不是代码 |
| 连续落后周数（达到即提醒） | 3 | `lag_count` | 3 | 一致（表格按周，平台按检查点，含月末） |
| 月度低效线（月度完成度低于） | 0.7 | `low_line` | 0.7 | 一致 |
| 持续低效月数（近 3 个已结月中达到即判持续低效） | 2 | `low_months` | 2 | 一致 |

表格里还有一个「飞书搭建指南」，那是**另一条路线**（用飞书多维表格搭），平台化之后不再需要，保留是为了对照。


## 六、种子数据

`种子数据_真实人员.json` 是十二月的真实拆分，含：

- 7 名成员（闪电Leo 为管理员；星宇归品牌经营部；亚伟、Kalvin.Dai 归 AIGC创新部；黄咏琦归 TOKEN业务部；胡一凡归内容业务部；张文瀚归 BPO业务部）
- 3 个目标类型、8 条业务线
- 公司月目标：GMV 1000、浪花收入 30、管理咨询收入 20（单位万元）
- 15 行目标

使用时要注意：

- **业务线负责人没有预设**（`负责人` 为空），需要管理员在工作台里自己设。
- **整体金额拆分是示例，待用户确认**，见 `05_待确认事项.md`。种子数据里每一行的 `备注` 已经写明。
- 「待导入成员」里是公司在职花名册的姓名与部门（只有姓名和部门）。是否导入由管理员决定，建议用「批量添加」逐步加。
- **不要导入花名册里的其他任何字段**（身份证、银行卡、手机号等）。
- 已离职的同事不在数据里，其原来的两笔协同金额已并入主责：AI画面（闪电Leo）8，AI成片分润（Kalvin.Dai）6。
