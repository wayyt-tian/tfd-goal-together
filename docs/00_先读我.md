# 锅气家族目标共创台 · 研发交付包 v0.3

交付日期：2026-11-25（北京时间）。当前应用版本 0.4.0，包标识 `goal-together-v0.4-formal-20261125`。面向接手迭代的研发助手和工程师，也可以给管理者直接体验。

2026-11-25 已完成 PostgreSQL 16 与 React 19 重构。服务端仍为 Node.js JavaScript，前端由 Vite 构建。保留原有页面功能、布局、品牌素材和业务规则，只重建虚构演示数据，不读取或迁移 SQLite 数据。

正式模式与账号、组织和管理流程已于 v0.4 补齐，详见 [正式模式与账号管理](14_正式模式与账号管理.md)。正式与演示数据独立，正式库不带虚构数据。

## 先做这四件事

1. 从根目录运行 `npm ci`、`npm run db:setup`、`npm run build`、`npm start`。正式入口 `/formal/`，演示 `/demo/`；只体验虚构演示可运行 `npm run demo`。
2. 阅读 [AGENTS.md](../AGENTS.md)、[业务规则与权限](02_业务规则与权限.md)、[已知问题与迭代路线](07_已知问题与迭代路线.md)。
3. 运行 `npm test` 建立回归基线；浏览器交互使用 `npm run test:browser`。
4. 阅读 [本地开发与部署](05_本地开发与数据续接.md)、[重构与验证](13_PostgreSQL与React重构.md)。正式库、测试库、演示库必须分开。

环境：Node.js 22.13+、PostgreSQL 16。默认本地数据库使用 Docker 内已缓存的 `postgres:16-alpine`；导入及对应测试使用 Python 3.9+。

## 这一版解决了什么

| 用户诉求 | v0.3 的做法 |
| --- | --- |
| 员工一眼看清自己关联了哪些组织目标，还能管理自定义目标 | 「我的」首页只放和我有关的卡片，每张卡片顶上写着它属于哪个公司目标；自主目标可以挂靠到公司目标，也可以只给自己用 |
| 上级看到下级的目标和进度 | 按「直属上级」汇报线 + 「部门负责人」两条线算团队；「团队」页按部门折叠，先看需要关心的人 |
| 从公司整体目标逐层下探 | 「目标地图」从公司北极星目标开始，一层层点进去；每层都能看拆解、成员、进展三个面 |
| 实时感知最新进展和风险，有呼吸感 | 服务器推送 + 增量同步，新进展几秒内出现在所有相关的人那里；顶栏呼吸灯、新动态滑入、数字变化闪一下；「你不在的时候」摘要；锅气小助手用几句人话指出最值得看的事 |
| 任何人想到高价值的事都能马上建 | 全局「＋新建」一句话建目标，挂到任何自己参与的目标下面；上级和公司总览实时看到新增 |
| 轻松、共创，不像传统绩效系统 | 不打分、不排名；暖橙品牌色、IP 表情、点赞；状态用「顺利 / 稍慢 / 落后」而不是红黄牌；起步 3 天不判落后 |
| 50–80 人时新手也好用 | 顶栏只有 4 项；新手三步引导；列表分页 + 搜索；团队按部门折叠；选人器可搜可筛；80 人规模自动测试 |

## 数据与隐私

包内没有真实数据库、登录凭据、会话、备份或通讯录原件。演示数据和截图里的人名、数字全部虚构；测试只用虚构的人和号段（139 0000 xxxx 等）。

旧数据库由原环境保留，本轮未连接、搬迁或修改。新版本使用独立 PostgreSQL 数据库，`.env`、数据库卷和备份不进入源码交付。

当前可执行契约以 `src/`、`web/` 代码和本包 01–08 文档为准；用户后续的明确指令优先。
