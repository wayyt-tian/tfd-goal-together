# 业务规则与权限

本文件描述不能随意改动的行为。实现集中在 `src/lib/goals.cjs`（目标领域）和 `src/application.cjs` 及 `src/lib/permissions.cjs`（登录、组织、成员和管理授权）。改动这些规则前，先和用户确认，并同步测试。

## 一、目标树

每个目标只有一个**负责人**，可以有最多 30 位**协作者**；目标可以继续往下拆，形成任意层级的树，最多 6 层。根目标分两种范围，子目标继承根的范围：

| 范围 | 谁能建根目标 | 用途 |
| --- | --- | --- |
| 公司目标 `company` | 只有公司负责人 | 公司北极星目标及其逐层拆解；进展逐层汇总到公司 |
| 自主目标 `personal` | 任何人（负责人就是发起人）；上级也可以为团队成员发起 | 自己想推进的事；可以「挂靠」（`align_id`）到自己看得到的公司目标表明方向，但**不计入公司汇总** |

目标有两种类型：**有数字**（`measure`，有单位和目标值）和**做完就行**（`action`）。已经有进展或子目标的目标不能切换类型。

「拆给成员」一次给多人各建一个子目标（一次 1–80 人）；份额合计超过上层目标时只提示（相当于留冲刺空间），不拦截。归属组织（`org_ids`）最多 10 个，只用于描述和筛选，不扩大任何人的查看范围。周期最长 400 天。

## 二、汇总与节奏

| 情况 | 完成度 |
| --- | --- |
| 有数字 | 自己的有效进展之和 + 同单位「有数字」子目标的累计，除以目标值。不同单位的子目标不相加 |
| 做完就行、有子目标 | 子目标完成度的平均（每项最多按 100% 计） |
| 做完就行、没有子目标 | 标记完成即 100%，否则 0 |

时间进度按目标自己的起止日期计算。差额（`gap`）= 目标值 − 已分到下一层的同单位目标值之和，负数表示超配，只提示。

汇总始终由服务端用**整棵树**计算，包括当前用户看不到的子目标；看不到的部分只告诉数量（`hiddenChildren`），不泄露内容。

状态只描述节奏，不评价人：

| 状态 | 显示 | 条件 |
| --- | --- | --- |
| `done` | 已达成 | 手动标记完成；或数字达到目标值；或有子目标的「做完就行」全部完成 |
| `upcoming` | 未开始 | 今天早于开始日期 |
| `neutral` | 未定数字 | 有数字但还没定目标值 |
| `ok` | 顺利 | 完成度落后时间进度不超过 5 个点（`healthLine`） |
| `watch` | 稍慢 | 落后 5–15 个点（`watchLine`）；没有子目标的「做完就行」离截止不到 2 天 |
| `risk` | 落后 | 落后超过 15 个点；没有子目标的「做完就行」已过截止日 |

**观察期**：末端目标从开始（或创建，取较晚者）的头 3 天不判稍慢或落后，给大家起步的时间。**很久没更新**：末端目标进行中，超过 `staleDays`（默认 7 天）没有自己的进展。**需要支持**：最近一次自评选了“需要支持”，单独显示紫色标签并计数，不改动按节奏算出的状态。

数字越过 100% 时发一条「达成」动态（喜报），所有能看到的人都会收到。

## 三、组织与团队

部门最多两级，每个部门可以设一位负责人。成员可以设「直属上级」（汇报线），系统拒绝循环汇报。成员离职（停用）后：会话立即失效、部门负责人任命取消、他的下属自动改为向他的上级汇报；他负责的目标和历史进展都保留，可以一键交接给在职同事。

一个人的**团队** = 汇报线上的所有下属（逐级向下）∪ 他负责的部门（含下级部门）里的全部成员。有团队的人角色显示为「业务负责人」，多出「团队」入口。

## 四、谁能看到什么

公司负责人能看到全部。其他人能看到：

1. 自己或团队成员**负责或协作**的目标，以及这些目标的全部下层；
2. 上面这些目标的全部上层，作为上下文（让人知道“我的努力汇总到哪里”）；
3. 规则里把「公司目标全员公开」打开时（`openness = open`），全部公司目标；自主目标仍然只有相关的人和上级能看到。默认是 `path`（只看和自己有关的路径）。

看不到的目标，任何接口都按“不存在”（404）处理。动态、增量、详情、个人页都按同一套可见范围过滤。

## 五、谁能做什么

| 操作 | 谁可以 |
| --- | --- |
| 建公司根目标、改它的数字、归档它 | 只有公司负责人 |
| 在目标下加子目标 | 负责人、协作者，以及能「管理」这个目标的人 |
| 拆给成员 | 同上，且目标还没到第 6 层 |
| 记进展（填数字） | 只有负责人和协作者 |
| 留言（不填数字） | 能看到这个目标的人 |
| 改标题、描述、日期等 | 负责人、创建人、能管理的人 |
| 改目标值、单位、类型、负责人；归档 | 创建人、能管理的人（公司根目标只有公司负责人）。负责人本人不能给自己改目标值，可以在进展里说明情况 |
| 标记完成 / 重新打开 | 负责人、协作者、能改描述的人 |
| 加入 / 退出协作 | 能看到这个公司目标的人（负责人除外）；自主目标由发起人邀请 |
| 撤回 / 恢复进展 | 只有记录人本人 |
| 管理普通成员、组织、通讯录 | 公司负责人、系统管理员；涉及扩大系统管理员本人团队范围的任命仅公司负责人 |
| 任命管理角色、调整规则、目标交接、完整备份 | 只有公司负责人 |

「能管理」= 公司负责人；或者是这个目标任一上层目标的负责人；或者这个目标的负责人在他的团队里。

## 六、进展流水

进展是增量流水：每一笔记“这次新增多少”。数字可以为空（只留言），可以是负数（冲减、退款），负数必须写原因，且这个目标自己的累计不能变成负数。日期不能晚于今天。同一个编号重复提交只算一次（防止网络重试记两遍）。

撤回只标记 `voided_at`，原记录永远保留；撤回或恢复导致累计为负时拒绝。**任何情况下都不物理删除进展。**

## 七、并发与实时

编辑和归档目标必须带当前 `version`；别人刚改过时返回 409，前端载入最新内容让用户再确认。成员和部门的编辑、停用及部门恢复也必须携带版本号，过期返回 409。

所有写操作在一个事务里完成并写一条事件，提交后通过服务器推送通知在线的人；组织或成员变化时要求客户端整体刷新。

## 八、登录与安全

正式登录使用手机号和密码；首次负责人初始化需要本机私有凭证，账号开通和密码找回使用 30 分钟、单次有效的设置密码链接。旧后四位哈希保留但不再用于登录。密码为 10–128 个字符，异步 scrypt 加盐哈希保存。同一来源与手机号连续输错 5 次锁定 10 分钟。会话 Cookie 为 HttpOnly + SameSite=Strict，有效 8 小时；写操作要求 JSON、同源和 CSRF。正式和演示的数据、会话、连接与缓存独立。

至少保留一位在职公司负责人；不能停用当前账号。密码重置、停用和授权变化会撤销会话并断开实时连接。系统管理员可管理普通账号和组织，但不能管理管理人员、调整全局规则、下载完整备份，不能通过组织操作扩大本人业务可见范围。业务负责人仍由部门与汇报关系推导。完整角色矩阵和操作流程见 [正式模式与账号管理](14_正式模式与账号管理.md)。

## 九、规则设置（设置 › 规则，仅公司负责人）

| 设置 | 默认 | 范围 |
| --- | --- | --- |
| 公司目标可见范围 `openness` | `path`：只看和自己有关的路径 | `path` / `open` |
| 多久没更新算很久 `staleDays` | 7 天 | 3–30 天 |
| 稍慢阈值 `healthLine` | 5 个点 | 0–50 个点 |
| 落后阈值 `watchLine` | 15 个点 | 不小于稍慢阈值，最多 50 个点 |
