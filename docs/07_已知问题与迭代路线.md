# 已知问题与迭代路线

下面是边界说明和建议，不代表用户已经授权全部实施。接手的人按用户的新需求排优先级。

## 一、本轮范围

当前已切换 PostgreSQL 与 React。旧 SQLite 环境和历史运营记录由原环境保留，本轮没有连接或迁移。原 v0.3 的升级演练记录仅作为历史背景，不能视为当前库的数据状态。

## 三、建议的后续顺序

1. **先投用**：处理第一节的运营项，挑一个业务方向试跑两周，收集“记一笔”和“拆给成员”的真实使用反馈。
2. **再部署**：确定访问方式（局域网 / 内网穿透 / 云主机），解决 L-01、L-02、L-03。
3. **按需增强**：周期模板（每月一键复制上月的拆解结构）、飞书每周摘要、跨期对比的稳定标识（L-12）。

界面上保持现在的原则：每页只回答一个问题，信息按需展开，不要为了加功能把 80 人的卡片铺满一屏。

## 四、尚未交付的能力

奖金计算、审批流、附件凭证、短信服务、自动提醒、生产发布、80 人同时提交的压力测试、经营驱动公式（例如 GMV = 流量 × 转化 × 客单价）。用户提出其中一项时，先明确输入、权限和验收标准，再增量实现。

v0.4 正式模式、账号及管理流程验收见 [正式模式与账号管理](14_正式模式与账号管理.md)。备份为页面手动创建，未接入定时调度。
