# 数据模型与 HTTP 接口

本文件保留目标领域接口说明；v0.4 账号、模式前缀和新增管理接口以 [正式模式与账号管理](14_正式模式与账号管理.md) 为准。实例内入口已移动到 `src/application.cjs`。`docs/references/original/` 里的旧接口清单和 v0.2 的 `/api/state` 整份快照接口都已不再使用。

## 存储

数据库由 `DATABASE_URL` 指定，使用 PostgreSQL 16；`DATABASE_SCHEMA` 默认为 `public`。初始化 SQL 位于 `src/db/migrations/001-initial.sql`，执行版本记录在 `schema_migrations`。金额及进度数值采用 `NUMERIC(24,4)`，日期为 `DATE`，时间为 `TIMESTAMPTZ`，结构字段为 `JSONB`。保留原接口和字段表现。SQL 暂未定义外键，完整性由服务端校验。`event_clock` 在事务中推进游标，`checkins.ordinal` 保留同时间流水的顺序。

| 表 | 内容 |
| --- | --- |
| `metadata` | 键值：`configured`、`revision`、`settings`（规则）、`demoPersonas`、`goalsMigrated`（v0.2 迁移报告）、`performance_legacy`（v0.2 原始业务 JSON）、`directoryInitialization`（通讯录导入摘要） |
| `departments` | 两级部门、部门负责人、软删除 |
| `users` | 成员：姓名、手机号、旧后四位哈希（停用）、密码哈希、版本、部门、角色（owner / system_admin / member）、在职、**直属上级**、职位 |
| `sessions` | 会话令牌哈希、CSRF、过期时间 |
| `audit` | 关键操作审计 |
| `directory_profiles` | 通讯录来源编号、别名、通讯录里的直属上级 |
| `goals` | 目标树：父目标、范围、类型、标题、说明、单位、目标值、起止日期、负责人、归属组织、挂靠、版本、归档、完成、游标、v0.2 来源编号 |
| `goal_members` | 协作者 |
| `checkins` | 进展流水（增量数字可空、说明、自评、日期、撤回信息、是否模拟） |
| `events` | 事件流水（动态和增量游标） |
| `cheers` | 点赞 |
| `user_state` | 每人的已读游标、是否看过新手引导 |

从 v0.2 升级的库里还会保留 `performance_trash`（v0.2 回收站），v0.3 不读不写。

## 事件类型

| 类型 | 何时产生 | 出现在动态里 |
| --- | --- | --- |
| `goal.created` | 新建目标（含自主目标、子目标） | 是 |
| `goal.split` | 拆给成员（一次一条，带人数） | 是 |
| `goal.updated` | 修改标题、数字、日期、负责人等（payload 里有变化前后） | 是 |
| `goal.done` / `goal.reopened` | 标记完成 / 重新打开 | 是 |
| `goal.achieved` | 数字越过 100%（喜报） | 是 |
| `goal.archived` / `goal.restored` | 归档 / 恢复（整棵子树） | 是 |
| `checkin.created` | 记一笔（数字或留言）；撤回后在 payload 里标 `voided` | 是 |
| `member.joined` / `member.added` | 自己加入协作 / 被加为协作者 | 是 |
| `checkin.voided` / `checkin.restored` | 撤回 / 恢复进展 | 否（只更新原动态的标记） |
| `member.left` | 退出协作 | 否 |
| `org.changed` | 部门、成员、汇报线、初始化、交接（`action: goal.handover`） | 否，触发客户端整体刷新 |
| `settings.changed` | 规则调整 | 否，触发客户端整体刷新 |

## 主要对象

**bootstrap**（登录、`/api/session`、`/api/bootstrap` 返回的 `data`）：`me`、`access`（`role`: admin / lead / member，`teamIds`、`directReportIds`、`managedDepartmentIds`）、`settings`、`today`、`seq`、`lastSeenSeq`、`lastSeenAt`、`onboarded`、`cheersReceived`、`people`、`departments`、`goals`（只含可见目标）、`demo`、`demoLive`、`directoryInitialization`、`migration`。

**目标**：`id, parentId, scope, kind, title, note, unit, target, startDate, endDate, ownerId, memberIds, orgIds, alignId, createdBy, createdAt, updatedAt, version, doneAt, sort, seq, context, hiddenChildren, stat, perms`。`context=true` 表示只是作为上下文可见的上层目标。`perms` 是当前用户对它能做的事：`edit, core, child, checkin, archive, join`。

**汇总 `stat`**：`value, target, completion, timeProgress, deviation, status, signal, stale, assigned, gap, childCount, leaf{total,risk,watch,done,help,stale}, lastDate, ownLast, updates, daysLeft, people`。规则见第 02 份文档。

**增量**：`{ seq, goals, removed, events, reload }`。

**动态条目**：`{ seq, at, actorId, type, goalId, refId, data, cheers, cheered }`，列表返回 `{ items, next }`，`next` 用作下一页的 `before`。

## 接口

通用约定：写操作要求 `Content-Type: application/json`、请求头 `X-CSRF-Token`、同源；成功返回 `{ ok: true, result, delta? }`，请求头带 `X-Since` 时附带增量。错误返回 `{ error: "中文提示" }`：401 未登录，403 无权限或 CSRF 失效，404 不存在或看不到，409 冲突，415 不是 JSON，429 登录尝试过多。完整的请求和响应样例见 `docs/examples/api-examples.json`（24 个，真实调用生成）。

| 方法与路径 | 说明 | 权限 |
| --- | --- | --- |
| `GET /api/session` | 是否已初始化、是否登录；已登录时带 `data` 和 `csrf` | 公开 |
| `POST /api/setup` | 首次配置公司负责人 `{name, phone, password, setupToken}`，只能一次 | 公开（仅未初始化时） |
| `POST /api/login` | `{phone, password}` | 公开，限流 |
| `POST /api/logout` | 退出并断开推送 | 登录 |
| `GET /api/demo/personas`、`POST /api/demo/login` | 演示身份列表和一键进入 | 仅演示模式 |
| `GET /api/bootstrap` | 整体数据 | 登录 |
| `GET /api/delta?since=` | 增量 | 登录 |
| `GET /api/stream` | 服务器推送：`hello`、`seq`、`cheer`、`presence` | 登录 |
| `GET /api/events?limit&before&filter&goal&subtree&person` | 动态；`filter` 为 `all / mine / team / help / new` | 登录，按可见范围 |
| `POST /api/goals` | 新建目标：`{id?, parentId?, scope, kind, title, note?, unit?, target?, startDate, endDate, ownerId?, memberIds?, orgIds?, alignId?}`；有父目标时范围和周期默认继承 | 见第 02 份文档 |
| `GET /api/goals/:id` | 详情：`{ goal, contributions, aligned, hiddenLeaves }` | 可见 |
| `PATCH /api/goals/:id` | 修改，必须带 `version` | 能改描述 / 能改核心字段 |
| `POST /api/goals/:id/split` | `{items: [{ownerId, title?, target?, note?, allowSecond?}]}` | 能加子目标 |
| `POST /api/goals/:id/join` | 加入协作；`{leave: true}` 退出 | 可见的公司目标 |
| `POST /api/goals/:id/done` | 标记完成；`{done: false}` 重新打开 | 负责人、协作者、能改描述的人 |
| `POST /api/goals/:id/archive` | `{version, reason?}` 归档整棵子树 | 能改核心字段 |
| `POST /api/goals/:id/restore` | 恢复归档 | 能改核心字段 |
| `POST /api/goals/:id/checkins` | 记一笔：`{id?, value?, note?, signal?: ok/watch/help, date?}` | 填数字：负责人和协作者；留言：可见 |
| `POST /api/checkins/:id/void` | 撤回 `{reason?}`；恢复 `{restore: true}` | 记录人本人 |
| `GET /api/checkins?before=` | 我记过的进展 | 登录 |
| `GET /api/archived` | 已归档目标 | 登录（按权限过滤） |
| `POST /api/events/:seq/cheer` | 点赞 / 取消 | 可见 |
| `POST /api/me/seen` | 记录已读游标 `{seq}` 或 `{onboarded: true}` | 登录 |
| `GET /api/settings`、`PUT /api/settings` | 读取 / 调整规则 | 读：登录；改：公司负责人 |
| `GET /api/admin/users` | 成员列表和通讯录导入摘要；名下目标数仅公司负责人返回，系统管理员不读取全局目标计数 | 公司负责人、系统管理员 |
| `POST /api/admin/users/:id/handover` | 一键交接 `{toId}`：把这个人名下的全部目标（含已归档）交给在职同事，只改负责人，历史记录人不变；返回 `{count, open}` | 公司负责人 |
| `POST /api/admin/directory-managers` | 按通讯录里的直属上级补汇报线 | 公司负责人 |
| `POST /api/admin/backups`、`GET /api/admin/backups/:id/download` | 创建备份 / 下载已有备份 | 公司负责人 |
| `POST /api/departments`、`PUT/DELETE /api/departments/:id` | 部门增改停用；更新及停用带版本 | 公司负责人、系统管理员 |
| `POST /api/users`、`PUT/DELETE /api/users/:id` | 成员增改停用；更新及停用带版本 | 公司负责人；系统管理员仅普通成员 |

静态文件：`/`、`/index.html`、`/css/*`、`/js/*`、`/assets/brand/<名称>.(webp|png|svg)`、`/fonts/dm-sans-latin.woff2`。其他路径（源码、数据目录、`assets/brand/source/`、以点开头的路径、越级路径）一律 404。所有响应带 CSP、`X-Content-Type-Options`、`Referrer-Policy` 等安全头。

v0.4 新增 `account_tokens`、`directory_imports`、`backups` 表，成员和部门增加版本，详见 `002-formal.sql`。正式模式接口需加 `/formal`，演示需加 `/demo`。
