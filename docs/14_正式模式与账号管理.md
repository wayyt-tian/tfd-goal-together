# 正式模式与账号管理 · v0.4

2026-11-25。本版在 React 与 PostgreSQL 重构基础上，补齐正式使用流程。正式与演示共用界面和局域网入口，但分别持有数据库连接、会话、读模型、实时订阅和备份目录；切换不会转换、复制或清空另一模式的数据。

## 启动与首次使用

```sh
npm ci
npm run db:setup
npm run build
HOST=0.0.0.0 PORT=4180 npm start
```

访问 `http://本机局域网地址:4180/formal/`；演示位于 `/demo/`。根地址默认进入正式模式，登录页和头像菜单均可切换；有未保存输入时提示确认。`npm run demo` 仍是只连接演示库的独立体验环境，没有正式模式入口。

正式库使用 `DATABASE_URL`，演示使用 `DEMO_DATABASE_URL` 和随机临时空间。两个数据库必须独立；已有空间的模式标记不匹配时拒绝启动。正式首次启动没有虚构成员、目标或预设部门，仅有待初始化的负责人占位记录。数据库正式数据持久保留，演示临时空间在正常停止时清除。

首次配置需填写负责人姓名、手机号、密码、确认密码和初始化凭证。凭证只保存在服务器本机 `${GUOQI_DATA_DIR:-.data}/formal/setup-token.json`，24 小时有效，成功初始化后删除；已初始化实例重启不再创建此文件。过期时重启未初始化实例会重新生成。不要把该文件放到公开目录。独立正式实例（`GUOQI_DEMO=0`）的文件直接位于本地数据目录下。

本机本轮交付服务使用 `192.168.1.32:4180`，正式数据存入本项目新建的独立 `goal_together_formal` 库，原连接对应数据库未转换或清空。`.env` 中记录实际连接，原配置私下保存在 `.data/config-before-formal.env`。

## 账号全流程

1. 公司负责人初始化后，在「设置 → 组织」创建部门，在「设置 → 成员」开通账号，或上传通讯录导入。
2. 新建账号后显示一次性设置密码链接；管理员手动交给本人，不自动发送消息。已有账号可在资料中重新生成。
3. 成员打开链接设置密码，再以手机号、密码登录。链接 30 分钟有效、仅一次可用；新链接撤销旧链接，也撤销该账号既有会话。
4. 「头像 → 账户设置」查看本人资料、修改密码、退出全部设备。密码长度 10–128 字符，空格按原样参与密码，不要求特殊字符组合。
5. 忘记密码联系管理员；停用后不能兑换链接或登录，恢复账号后可重新生成链接。旧身份证后四位哈希保留在库内，但正式登录完全不使用它。

密码使用随机盐和异步 scrypt；链接令牌只存哈希，原值只在生成结果中显示。链接令牌位于网址 `#` 后的片段，不进入服务器访问路径。修改密码、重置、停用和账户授权变化会撤销会话；会话为 8 小时，Cookie 为 HttpOnly、SameSite=Strict，各模式 Cookie 名称和路径分别隔离。跨模式复制或改名 Cookie 均不能获得另一模式身份。

负责人本人无法登录时，服务器管理员可执行：

```sh
npm run account:recover -- --phone=负责人手机号
# 检查账号存在后，再生成一次性恢复链接：
npm run account:recover -- --phone=负责人手机号 --origin=http://局域网地址:4180 --apply
```

恢复命令只针对在职公司负责人，默认仅检查；恢复链接需交给本人，30 分钟内使用。命令输出包含一次性秘密，不应复制到共享日志。

## 角色与组织权限

| 身份 | 管理能力 | 目标可见范围 |
| --- | --- | --- |
| 公司负责人 | 管理任命、成员、组织、导入、规则、交接、完整日志、备份 | 全公司 |
| 系统管理员 | 普通成员账号、组织、导入、系统日志、运行状态 | 本人团队及目标关系，不自动扩大 |
| 业务负责人 | 由部门负责人或汇报关系自动产生，推进相关团队目标 | 沿用团队规则 |
| 成员 | 本人账户与目标协作 | 沿用目标关联规则 |

管理任命只由公司负责人执行。系统管理员不能修改或重置管理人员、授予管理身份、调整全局规则、下载完整备份；组织操作若会扩大其本人团队范围，也要求公司负责人操作。至少保留一位在职公司负责人；不能停用当前登录账号。服务端统一校验能力，前端隐藏入口只是辅助体验。

成员及部门的编辑、停用必须携带 `version`，过期返回 409；成员编辑可「载入最新资料」后重试。部门软删除后在「组织 → 已停用部门」恢复，可调整名称及上级，以解决同名或上级尚未恢复等冲突。离职成员的下属向其原上级汇报，目标和历史流水保留，由公司负责人交接。

## 通讯录、日志与备份

成员页提供空白 XLSX 模板、预览、确认导入和报告下载。最多 500 人、文件 5 MB，解压体积也受限。必需列为用户 ID、姓名、联系手机、部门；部门使用「公司/一级部门/二级部门」，直属上级使用手机号且必须包含在本次通讯录内。支持原有飞书导出格式，不自动连接飞书。

预览不会改成员、组织或目标；临时预览绑定操作者、组织版本和 30 分钟有效期。确认前重新校验，先备份，再在单个事务中执行；失败整体撤回，可以修正后重新预览。按来源编号、手机号、未配置手机号的同名账号匹配，不覆盖已有汇报线、不授予管理权限、不修改目标与进展。导入账号需另行生成设置密码链接。系统管理员不能通过导入修改管理人员。

「设置 → 数据」提供运行状态、备份及操作日志。系统管理员只看账号、组织及导入日志，公司负责人可查看完整审计；支持时间、操作人、操作类型筛选及分页。界面显示中文操作和对象名称，不显示令牌、哈希或内部路径。

备份创建用 POST，记录成功或失败；下载已有备份不重新生成文件。完整备份包含敏感账号与业务数据，仅公司负责人可下载。页面不支持覆盖恢复；服务器管理员使用独立新建空库验证：

```sh
npm run db:restore -- --file=/安全路径/备份.dump
# 通过环境注入新建空库连接，不在命令参数中填写密码：
# RESTORE_DATABASE_URL=...
npm run db:restore -- --file=/安全路径/备份.dump --apply
```

工具拒绝配置中的源库及非空目标库；恢复使用 PostgreSQL 16 工具及单事务，校验成员、目标、流水、事件游标和目标负责人。验证成功不会自动切换服务连接，需由服务器管理员安排连接切换。备份、初始化凭证和运行配置均不打入源码交付。

## 接口与实现

双模式接口分别以 `/formal/api`、`/demo/api` 开头；以下为模式内相对路径。未带模式前缀的接口只在独立实例中可用。

| 接口 | 行为 |
| --- | --- |
| `GET /api/session` | 模式、可用模式、初始化状态；已登录时返回能力清单 |
| `POST /api/setup` | `{name,phone,password,setupToken}`，只初始化一次 |
| `POST /api/login` | `{phone,password}` |
| `GET /api/account` | 本人资料、角色及管理能力 |
| `POST /api/account/password` | `{currentPassword,password}`，撤销所有会话 |
| `POST /api/account/sessions/revoke` | 退出全部设备 |
| `POST /api/admin/users/:id/activation` | 生成一次性设置链接 |
| `POST /api/account/activate` | `{token,password}`，原子兑换一次，不自动登录 |
| `GET /api/admin/departments/inactive` | 已停用部门 |
| `POST /api/departments/:id/restore` | `{version,name?,parentId?}` |
| `GET /api/admin/directory/template` | 下载 XLSX 模板 |
| `POST /api/admin/directory/preview` | `{content:文件Base64}`，返回预览编号、报告及有效期 |
| `POST /api/admin/directory/:id/apply` | 确认导入，返回报告 |
| `GET /api/admin/audit` | `from,to,actor,action,before`，每页 30 条 |
| `GET /api/admin/status` | 数据库状态、版本、运行时长、最近备份结果 |
| `GET/POST /api/admin/backups` | 最近 50 条备份 / 创建备份 |
| `GET /api/admin/backups/:id/download` | 下载已有备份 |

`src/server.cjs` 负责入口分流；`src/application.cjs` 负责实例内事务与路由；`src/lib/accounts.cjs`、`permissions.cjs`、`management.cjs`、`directory.cjs` 分别处理账号、授权、管理接口及导入。目标权限和汇总仍由目标领域负责。静态资源继续共用内容指纹、压缩和缓存，不对外提供源码。

增量迁移 `002-formal.sql` 新增密码、一次性凭证、成员/部门版本、导入任务和备份记录。升级已存在 PostgreSQL 空间前先备份并保存 `migration-report.json`；`status=applied` 表示升级完成，`prepared` 表示已有备份但尚未完成。迁移撤销旧会话，原凭据和业务记录保留。未读取或迁移 SQLite。

本轮不提供外部身份服务、消息发送、审批、定时备份调度或在线覆盖恢复；未开展压力测试及真实设备触控、完整读屏审查。已有业务页面布局保持，新增账号与管理界面沿用现有样式。
